# 墨观项目整体设计与开源产品规范

**版本：v2.1**  
**日期：2026 年 7 月 28 日**  
**状态：现行总体规范**  
**适用范围：产品、设计、数据、知识库、模型、开发与社区治理**

> 本文规定墨观“必须是什么、如何运行、哪些内容不得越界”。P0、P1及后续开发计划必须服从本文；与本文冲突的旧阶段文档视为待修订，不再作为产品定义依据。

## 一、总体原则

1. 墨观是开源的世界观察、解释与推演系统。
2. WorldMonitor 只作为开源参考仓库和组件来源，不作为墨观的核心引擎或运行依赖。
3. 古籍知识库、古今映射、事势星云和推演复盘是墨观的核心产品能力。
4. 现代事实、来源观点、古籍原义、墨观解释和未来推演必须分层保存与展示。
5. 产品按“观象—纪事—察势—稽古—通变—候验”的顺序运行，不得颠倒。
6. 开源代码不自动赋予外部数据、现代整理本、图片、译注或品牌的再使用权。
7. 所有公开判断必须可追溯、可修订、可反驳、可复盘。

## 二、系统边界

数据源准入、开放等级、登记字段和退出机制统一遵循《墨观开放数据源宪章与首批登记表》。任何来源未完成登记前，只能进入实验区。

### 墨观负责

- 汇集公开世界信号；
- 建立可追溯事件档案；
- 展示事物之间有依据的影响关系；
- 建设先秦至唐宋的结构化古籍知识库；
- 形成有边界的古今解释；
- 发布时立即给出明确判断、近日信号、一候走向和三候演变；
- 用每日新事实验证和复盘旧判断。

### 墨观不负责

- 取代原始新闻、政府公告、科学数据库或专业终端；
- 提供分钟级交易、军事行动或安全关键决策；
- 追踪并展示敏感个人实时轨迹；
- 以古典理论修改现代观测事实；
- 为个人命运、疾病、投资收益或战争结果作保证；
- 把无法获得的数据补造成正常值；
- 通过语言模型自动生成并发布未经审核的重要事实或古籍引文。

## 三、六个核心系统

### 1. 观象系统

#### 目标

发现值得进入墨观的现实信号。

#### 输入

- 经独立审计的开源适配器；
- 官方机构与国际组织数据；
- 新闻与公开 RSS；
- 天文、天气、灾害、市场、贸易、航运、航空、公共卫生和基础设施数据；
- 用户提交的公开链接、截图和文字线索。

#### 强制输出

- 来源；
- 抓取或观测时间；
- 数据代表的时间；
- 时区；
- 原始链接或数据标识；
- 新鲜度；
- 可用、陈旧、缺失、错误或受限状态；
- 数据许可与署名要求。

#### 禁止

- 将缺失值显示为零；
- 将演示数据显示为真实状态；
- 将单一新闻标题直接升级为正式事件；
- 隐藏上游服务依赖和数据延迟；
- 将WorldMonitor自身评分直接作为墨观结论。
- 将O3商业数据或X级规避访问控制数据设为核心依赖。

### 2. 纪事系统

#### 目标

形成稳定、可追溯、可持续更新的事件事实档案。

#### 事件最小字段

- `event_id`
- 标题与中性摘要；
- 事件发生时间与数据截止时间；
- 地点与涉及主体；
- 已确认事实；
- 来源观点；
- 未经确认的主张；
- 未知事项；
- 支持来源与反向来源；
- 修订历史；
- 当前状态；
- 进入正式分析的审核记录。

#### 规则

1. 默认观察过去三十个有效日。
2. 同一事件的新报道优先合并进时间线，不重复制造事件。
3. 用户提交内容默认是线索，不是事实。
4. 新闻摘要不得替代原始来源。
5. 事实变化必须新增版本，不得静默覆盖。

### 3. 察势系统

#### 目标

以“事势星云”呈现一件事的来源、直接影响、间接传导和待观察方向。

#### 节点类型

- 事件；
- 国家、组织、企业与公共主体；
- 地点、港口、海峡、资源区和基础设施；
- 商品、市场、产业链与贸易流；
- 社会、人口、公共卫生与舆论；
- 天文、天气、气候和自然事件；
- 古籍、概念与历史案例；
- 推演情景与观察信号。

#### 连线类型

- `causes`：有证据支持的导致关系；
- `amplifies`：加剧；
- `constrains`：抑制或约束；
- `depends_on`：依赖；
- `precedes`：时间上先于；
- `correlates_with`：相关但不声明因果；
- `claimed_by`：由某来源主张；
- `analogous_to`：历史或结构类比；
- `interpreted_through`：古典解释关系；
- `may_lead_to`：墨观推演中的可能传导；
- `invalidated`：此前关系后来未获验证。

#### 每条连线必须保存

- 起点、终点和方向；
- 关系类型；
- 首次出现和最后更新时间；
- 依据来源；
- 事实、来源主张、相关性、类比或推演状态；
- 建立者与审核状态；
- 失效或撤回原因。

#### 视觉规范

- 中心节点为当前事件；
- 第一圈展示已经确认的直接影响；
- 第二圈展示正在传导的间接影响；
- 第三圈展示近日、一候与三候内的待观察方向；
- 古籍与义理默认作为可切换图层，不与现代事实混成同一因果层；
- 实线表示事实关系，虚线表示推演，灰线表示相关性，断线表示未获验证；
- 点击节点和连线必须能够查看依据；
- 提供过去三十日至未来三候的时间轴，并标出每日验证与第五日一候结算；
- 星云首先服务理解，禁止为了视觉效果制造无意义节点和连线。

### 4. 稽古系统

#### 目标

建立墨观最核心、可长期积累的古籍知识基础设施。

#### 时间范围

- 理论源头：先秦至两汉；
- 制度集成：魏晋至隋唐；
- 观测精化：两宋；
- 现代校验：现代天文学史、文本校勘与版本研究。

#### 四层知识结构

1. **原典层**：作品、版本、篇章、原文和异文；
2. **注疏层**：历代解释、学派、时代和分歧；
3. **概念层**：天人、阴阳、五行、八卦、星官、分野、节气、灾异、治乱、流通和盛衰关系；
4. **通变规则层**：经过审核的现代应用条件、禁止外推、反证和历史复盘。

#### 每条材料必须保存

- 作品、篇章和原文；
- 作者或传统归属；
- 事件年代、记录年代、编纂年代和底本年代；
- 使用版本及来源锚点；
- 历史层级与材料功能；
- 现代释义；
- 异文与注疏分歧；
- 允许用途；
- 禁止外推；
- 反证或现代辨析；
- 版权与许可状态；
- 校核、公开引用和规则准入状态。

#### 三道门

1. 全文或元数据可检索，不等于可以公开引用；
2. 已校核且许可明确的片段，才可以公开引用；
3. 同时具备语境、边界、反证和人工批准的材料，才可以进入通变规则。

#### 版权规范

- 古籍原文进入公版，不等于现代标点、整理、译注、扫描和数据库成果可以自由复制；
- 每个底本单独记录来源和许可；
- 许可不清的材料只保存元数据和定位信息；
- 不得用模型记忆补写原文；
- 开源仓库不得收录没有再分发权的文件。

### 5. 通变系统

#### 目标

在现代事实不被改变的前提下，使用古典概念解释事件的变化结构。

#### 固定输出

1. 当前事实和数据截止时间；
2. 需要解释的现实功能特征；
3. 相关古籍原文和历史语境；
4. 古今映射属于原义、后世解释还是现代类比；
5. 事件当前所处阶段；
6. 主要解释；
7. 异说、反向解释和未知事项；
8. 不能由该框架推出的结论；
9. 对候验层的观察建议。

#### 五行规范

五行只描述功能、关系、阶段和变化，不给现代实体贴永久标签。

- 木：生发、扩展、疏通；
- 火：显现、加速、剧烈转化；
- 土：承载、统合、稳定；
- 金：收敛、切割、规范、执行；
- 水：流动、渗透、储藏、运输。

上述词义只是工作索引。任何具体使用必须回到已准入古籍和事件现实特征，不能仅凭关键词匹配。

### 6. 候验系统

#### 目标

在发布时立即给出明确、可回看的阶段性走向，并由每日新事实验证。十五日是最长复盘窗口，不是用户获得结论前的等待期。

#### 时间结构

- 基线：发布前过去三十个有效日；
- 当下：发布时立即给出明确结论；
- 近日：列出未来二十四至七十二小时的关键信号；
- 一候：第五个自然日形成阶段性小结；
- 三候：第十五个自然日形成完整周期复盘；
- 更新：每日；出现重大转折时立即发布新版本，不等待结算日。

#### 固定字段

- 推演对象；
- 发布时点和事实截止时间；
- 过去三十日事实摘要；
- 古典解释链；
- 当下明确走向；
- 未来二十四至七十二小时观察信号；
- 一候之内的主要走向；
- 三候之内的完整演变；
- 阶段性变化；
- 需要观察的转折信号；
- 不支持该走向的新事实；
- 每日印证、偏离或转折；
- 新版本及其修改理由；
- 到期结果与错误分类。

#### 规则

- 不输出合成置信度；
- 不宣称对真实未来结果负责或作保证；
- 不以免责声明代替明确判断；
- 不因后来事实变化而覆盖旧版本；
- 事实错误、知识引用错误、映射错误和推演错误分别记录。

## 四、事实、知识与推演的分层

用户界面和数据模型必须区分：

1. **现代事实**：由现代来源直接支持；
2. **来源观点**：媒体、机构或个人的解释；
3. **古籍原义**：古籍在自身时代和文本中的含义；
4. **墨观通变**：墨观对古今关系的版本化解释；
5. **未来候验**：尚未发生、等待验证的走向。

任何一层都不得借另一层的权威替自己背书。

## 五、WorldMonitor参考与复用规范

### 定位

WorldMonitor 是观象前端、地图实现和数据适配器的参考仓库，不是墨观的事实来源、核心引擎或产品运行底座。

### 集成原则

- 只选择性复用能够脱离WorldMonitor账户、Pro服务与托管API独立运行的代码；
- 数据优先直接接入公开权威来源，不因上游已有面板就间接依赖其商业数据层；
- 任何复用代码都通过独立适配层接入，内部事件模型不绑定其字段；
- 保留上游项目版权、许可证和修改记录；
- 衍生平台代码按 AGPL 要求公开对应源代码；
- 使用墨观自己的名称、标识和视觉系统；
- 不提交上游或第三方 API 密钥；
- 对每个上游数据源重新审查条款，不假设 WorldMonitor 的许可覆盖其数据；
- 不把PRO、托管API、账户权限和官方缓存纳入墨观运行依赖；
- 优先保存原始来源链接和必要的结构化事实，不复制没有再分发权的新闻全文；
- WorldMonitor仓库不可用时，不应影响墨观的正常采集、纪事与推演。

### 禁止

- 把 WorldMonitor 的品牌改名后冒充原创；
- 把其 CII、AI简报或情景结果直接当作墨观结论；
- 把其模拟、演示或降级数据当作事实；
- 绕过上游访问控制、付费限制或许可要求；
- 因为项目开源就默认所有聚合数据可以再次出售或发布。
- 为保留大量无关面板而整体复制和长期维护WorldMonitor。

## 六、AI与人工分工

### AI可以

- 发现和去重线索；
- 拆分事实主张；
- 整理事件时间线；
- 检索古籍候选材料；
- 生成事势关系候选；
- 提出古今映射草案与反向解释；
- 格式化推演和复盘。

### AI不得独立

- 确认重要事实；
- 创造古籍原文或异文；
- 决定新五行规则；
- 把相关性升级为因果；
- 发布重要公共事件结论；
- 输出医疗、投资、军事行动或个人命运建议。

### 人工必须批准

- 正式事件入库；
- 古籍公开引用；
- 可执行通变规则；
- 重要事势连线；
- 正式候验发布与一候、三候结算；
- 错误修订与撤回。

## 七、界面规范

### 首页

首页必须在五秒内让用户知道：

- 墨观正在观察世界；
- 用户可以从真实星象和全球事件进入；
- 点击事件后可以查看事实、影响、古籍、解释与推演。

首页不展示内部筛选逻辑、模型流程或冗长方法说明，不使用无限新闻流。

### 事件页顺序

1. 阶段性事实反馈；
2. 明确推演结论和走向；
3. 过去三十日时间线；
4. 事势星云；
5. 古籍原文与历史语境；
6. 通变解释、异说与边界；
7. 近日信号、一候走向、三候演变与每日候验；
8. 来源、版本和修订记录。

### 视觉原则

- 星象必须基于真实现代星历；
- 地球和地图服务于定位，不以廉价三维效果制造“情报感”；
- 整体界面采用克制的世界观察Console风格，强调状态、时间、来源和操作，不复制WorldMonitor的品牌、布局和密集图层；
- Console只是交互语言，不得让产品看起来像军事指挥或金融交易终端；
- 事势星云服务于关系理解，不以节点数量制造复杂感；
- 古典气质来自文字、比例、留白与秩序，不堆叠符咒、粒子或伪古代装饰；
- 用户始终能够辨认事实、古籍、解释和推演。

### 地图技术原则

- UI、地图引擎、底图服务和事件数据必须相互解耦；
- P0优先采用`MapLibre GL JS + deck.gl`：MapLibre负责底图、定位和交互，deck.gl负责事件点、弧线、区域、热度与时间动画；
- 事势星云是语义关系图，不强行塞进地理地图；只有具有真实地理坐标的节点才进入地图；
- P0不引入独立重型三维地球。需要球体展示时先验证MapLibre globe投影；
- 当产品确实需要卫星轨道、高精度三维地形、3D Tiles或大规模时空对象时，再单独评估CesiumJS；
- NASA Web WorldWind可作为Apache 2.0的备选参考，但不作为首选新项目底座；
- 地图库开源不等于瓦片、卫星影像和地名服务免费开放，所有底图与影像必须单独登记来源、许可、配额和缓存边界。

## 八、开源仓库规范

建议长期结构：

```text
moguan/
├── guanxiang/       # 观象：外部感知适配器
├── jishi/           # 纪事：事件与事实档案
├── chashi/          # 察势：事势星云
├── jigu/            # 稽古：古籍知识库
├── tongbian/        # 通变：解释与映射
├── houyan/          # 候验：推演与复盘
├── apps/
│   └── web/         # 墨观网站
├── docs/            # 产品、方法、数据与治理文档
├── LICENSE
└── NOTICE
```

代码目录使用稳定的拼音或英文标识，用户界面统一显示中文古典名称。

仓库必须：

- 提供许可证、第三方声明和数据源清单；
- 提供安全提交密钥的说明；
- 对知识库贡献设置引用与许可检查；
- 对事实、知识和推演分别设置审查流程；
- 公开重要规则和版本变化；
- 不在仓库中保存真实用户隐私信息。

## 九、发布门槛

一项事件分析只有同时满足以下条件才能公开：

1. 事实来源和截止时间完整；
2. 未知事项明确；
3. 事势关系能够说明依据和状态；
4. 古籍引用达到公开引用门槛；
5. 古今映射说明原义、类比和边界；
6. 推演给出明确走向、观察窗口和转折信号；
7. 已创建不可静默覆盖的版本记录；
8. 不触犯产品安全与许可边界。

任何一项缺失时，系统可以公开事实页，但不得伪装成完整墨观分析。

## 十、优先级

### P0：验证完整闭环

- 已完成并归档的WorldMonitor本地评估；
- 一个不依赖WorldMonitor官方服务的观象适配层；
- 一个`MapLibre GL JS + deck.gl`地图技术样板；
- 三个连续事件档案；

## 十一、成功标准

早期不以图层数量、新闻数量或“预测命中率”作为唯一指标。

必须验证：

- 用户能否理解墨观是做什么的；
- 用户能否区分事实、关系、古籍、解释和推演；
- 事势星云是否帮助用户理解影响传导；
- 古籍内容是否愿意被阅读和核查；
- 用户是否会在第二天回来查看候验；
- 社区是否能够发现并修正事实、古籍和映射错误；
- 系统是否在数据缺失时诚实显示不可用。

## 十二、不可动摇的规范

1. 事实先于解释。
2. 纪事先于察势，稽古先于通变，通变先于候验。
3. 古籍必须回到具体来源、版本与时代。
4. WorldMonitor 是参考仓库，不是墨观底座。
5. 古籍知识库是核心基础设施，不是内容附件。
6. 事势星云的每条关系必须有类型、来源和状态。
7. 不把相关性、类比或推演写成已经确认的因果。
8. 不用模拟数据代替现实数据。
9. 不用置信度掩盖缺失依据。
10. 不静默修改事实、解释或推演历史。
11. 不提供个人命运、投资、军事行动或医疗建议。
12. 开源代码、外部数据、古籍版本和产品品牌分别遵守各自权利边界。

## 十三、最终表达

> **观象为耳目，纪事为尺度，察势为脉络，稽古为根本，通变为思辨，候验为归宿。**

墨观不以神秘解释世界，也不以现代数据否定古典知识。它公开保存两者如何相遇、如何形成判断，以及判断如何被现实检验。
