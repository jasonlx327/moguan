# 墨观 P0 范围与数据契约

**版本：v0.1**  
**日期：2026 年 7 月 23 日**  
**状态：阶段 0 冻结草案**

## 一、P0 要验证的问题

P0 只验证一个核心问题：

> 用户是否愿意从真实的中国传统星空进入地球，查看三项经过核验的公共事件，理解事实、古典解释与情景推演之间的差别，并愿意再次回来？

P0 不是全球情报系统，不是完整古籍数据库，也不是自动预测产品。

## 二、当前默认决定

| 项目 | P0 默认值 | 状态 |
|---|---|---|
| 固定日期 | 2026 年 7 月 23 日 | 暂定 |
| 数据截止时间 | 当日 08:00，中国标准时间 | 待确认 |
| 默认观察地点 | 上海 | 暂定 |
| 地球视角 | 全球 | 已确定 |

| 发布方式 | 人工审核后发布 | 已确定 |

默认日期和地点只用于固定原型，不代表长期产品只能服务上海或该日期。

## 三、P0 页面范围

P0 只建设四个主要页面或界面层：

### 1. 今日天地

- 固定日期与观察地点；
- 真实太阳、月球和五星位置；
- 三垣、二十八宿和首批主要星官；
- 一个真实天气主图层；
- 数据截止时间和来源状态；
- 三项入选事件入口。

### 2. 事件详情

- 发生了什么；
- 时间、地点、主体和事件类型；
- 入选原因与所属候选池；
- 支持证据、反向证据和未知事项；
- 事件时间线与后续观测点；
- 事实层、古典解释层和预测层。

### 3. 验期账本

- 情景 A／B／C；
- 触发条件和失效条件；
- 观察截止时间；
- 结算来源与判定标准；
- 到期结果和修订记录。

### 4. 事件研判抽屉

- 文字、链接和截图提交；
- 输入识别结果；
- 事实核验状态；
- 分析草稿；
- 方法边界和拒绝原因。

P0 不建设复杂后台。人工选题与审核先通过结构化 Markdown 或 JSON 文件完成。

## 四、统一数据外壳

所有可展示对象都必须具有下列公共字段。

| 字段 | 含义 | P0 要求 |
|---|---|---|
| `id` | 稳定唯一标识 | 必填，不因标题修改而变化 |
| `record_type` | 天象／天气／事件／原典／分析／预测／结算 | 必填 |
| `title` | 面向用户的名称 | 必填 |
| `observed_at` | 事实实际发生或观测时间 | 事实对象必填 |
| `published_at` | 原始来源发布时间 | 有来源时必填 |
| `collected_at` | 墨观采集时间 | 必填 |
| `cutoff_at` | 当前页面统一数据截止时间 | 必填 |
| `timezone` | 时间解释所用时区 | 必填 |
| `data_status` | 数据状态 | 必填 |
| `source_ids` | 支持该对象的来源列表 | 公开事实必填 |
| `confidence` | 当前层级置信度 | 必填 |
| `review_status` | 审核状态 | 必填 |
| `version` | 当前记录版本 | 必填 |
| `revision_note` | 修改原因 | 修改后必填 |

## 五、数据状态契约

页面上出现的任何数据必须属于以下一种状态。

| 状态 | 定义 | 页面表达 |
|---|---|---|
| `live` | 已接入真实来源并按约定频率更新 | 真实数据 |
| `delayed` | 真实数据，但更新存在已知延迟 | 延迟数据，并显示延迟时间 |
| `snapshot` | 真实来源在固定时间形成的不可变快照 | 固定快照 |
| `demo` | 用于验证设计或交互的演示内容 | 演示，不作为事实 |
| `missing` | 数据未获得、不可用或未通过质量门槛 | 暂无数据 |

### 强制规则

1. `demo` 不得使用“实时”“今日结论”等表达；
2. `missing` 不得使用视觉占位伪装成真实数据；
3. `delayed` 必须显示最后更新时间；
4. `snapshot` 必须显示快照时间和来源；
5. 页面不能通过颜色或动画暗示不存在的精度。

## 六、天象数据契约

### 时间与地点

| 字段 | 含义 |
|---|---|
| `datetime_utc` | 计算所用 UTC 时间 |
| `datetime_local` | 用户看到的当地时间 |
| `timezone` | IANA 时区 |
| `latitude` | 观察点纬度 |
| `longitude` | 观察点经度 |
| `elevation_m` | 海拔，可缺省 |

### 天体

每个太阳、月球或行星对象至少包含：

- 天体名称；
- 赤经、赤纬；
- 方位角、高度角；
- 是否位于地平线上；
- 视星等或亮度状态；
- 月相与照明比例，仅月球使用；
- 星历来源与计算版本；
- 计算时间和观察地点。

### 中国传统星空

每个星官对象至少包含：

- 星官名称；
- 所属三垣或二十八宿；
- 组成恒星的现代标识；
- 坐标历元；
- 历史来源层级；
- 名称异文；
- 当前映射置信度；
- 是否允许公开显示。

中国星官映射属于历史研究结果，不得与现代国际星座体系混写。

## 七、天气数据契约

P0 只选择一个主天气图层，其他图层不进入首版。

### 候选主图层

- 云层；
- 降水；
- 地表或近地面温度；
- 风场。

### 每个天气数据集必须包含

| 字段 | 含义 |
|---|---|
| `variable` | 云量／降水／温度／风等 |
| `unit` | 单位 |
| `valid_time` | 数据有效时间 |
| `run_time` | 模型起报或产品生成时间 |
| `data_kind` | 观测／再分析／预报 |
| `spatial_resolution` | 空间分辨率 |
| `temporal_resolution` | 时间分辨率 |
| `coverage` | 地理覆盖范围 |
| `source_id` | 数据来源 |
| `quality_note` | 缺测、延迟或已知限制 |

天气与公共事件没有可证明的直接关系时，页面必须显示“未发现直接影响”，不能强行建立联系。

## 八、事件候选数据契约

### 候选事件

| 字段 | 含义 |
|---|---|
| `event_id` | 稳定事件编号 |
| `event_pool` | 天地／生民／天下／流通 |
| `headline` | 中性事件标题 |
| `summary` | 已确认事实摘要 |
| `start_time` | 事件开始时间 |
| `latest_change_time` | 最近一次显著变化时间 |
| `locations` | 地点和空间范围 |
| `actors` | 相关主体 |
| `claims` | 可独立核验的事实主张 |
| `source_ids` | 支持与反向来源 |
| `unknowns` | 当前未知事项 |
| `next_signals` | 后续观测指标 |
| `observation_window` | 建议观察窗口 |

### 事件评分

| 维度 | 权重 |
|---|---:|
| 公共影响 | 30 |
| 变化强度 | 25 |
| 证据完整度 | 25 |
| 持续观察价值 | 15 |
| 信息时效性 | 5 |

古典理论契合度、视觉冲击力和社交媒体热度不进入评分。

### 入选事件新增字段

- 总分与各维度评分；
- 入选理由；
- 同类候选比较；
- 未入选候选及原因；
- 人工审核人；
- 审核时间；
- 发布版本。

## 九、疫情与公共卫生事件契约

疫情属于“生民之变”，但采用更高准入门槛。

### 事实字段

- 疾病或综合征名称；无法确认时使用中性描述；
- 报告地区和观察周期；
- 病例、住院、重症、死亡或医疗承载指标；
- 指标定义和统计口径；
- 公共卫生机构公告；
- 数据延迟与修订情况；
- 传播范围和变化方向；
- 对人口流动、政策或社会运行的影响。

### 禁止字段和输出

- 未经确认的病原体名称；
- 个人诊断；
- 治疗与用药建议；
- 根据天象直接预测疾病暴发；
- 用古代病因观念修改现代医学事实；
- 将单个病例渲染为群体疫情。

## 十、来源数据契约

每个来源必须单独登记。

| 字段 | 含义 |
|---|---|
| `source_id` | 来源编号 |
| `publisher` | 发布机构或作者 |
| `source_type` | 官方／学术／媒体／数据库／原典 |
| `title` | 原始标题 |
| `url_or_reference` | 链接或书目 |
| `published_at` | 发布时间 |
| `accessed_at` | 墨观访问时间 |
| `language` | 原始语言 |
| `primary_or_secondary` | 一手或二手来源 |
| `license_note` | 使用与引用限制 |
| `reliability_note` | 来源局限 |
| `archived_copy` | 是否保存合规快照 |

新闻转载不能伪装成第二个独立来源。多个媒体引用同一原始公告时，只算一条证据链。

## 十一、古籍材料数据契约

### 文献层级

- 理论源头层：先秦—两汉；
- 制度集成层：魏晋—隋唐；
- 观测精化层：两宋；
- 现代校验层：当代研究与星历。

### 每条古籍片段必须包含

| 字段 | 含义 |
|---|---|
| `passage_id` | 片段编号 |
| `work_title` | 作品名称 |
| `chapter` | 篇章 |
| `source_text` | 原文 |
| `context_before_after` | 必要上下文 |
| `historical_layer` | 历史层级 |
| `source_function` | 理论／占候／观测／历法／仪器／制度／史例／评论 |
| `event_date` | 被记录事件时间 |
| `record_date` | 原始记录形成时间 |
| `compilation_date` | 作品编纂时间 |
| `edition` | 当前底本 |
| `modern_paraphrase` | 现代释义 |
| `allowed_use` | 允许参与的分析环节 |
| `forbidden_inference` | 禁止外推 |
| `counterevidence` | 异说与反证 |
| `review_status` | 校核状态 |

未经校核的古籍片段可以检索，但不能参与公开结论。

## 十二、墨观分析数据契约

墨观分析不是事实，也不是古籍原文，必须单独存储。

| 字段 | 含义 |
|---|---|
| `analysis_id` | 分析编号 |
| `event_id` | 对应事件 |
| `fact_version` | 所依据的事实版本 |
| `passage_ids` | 所引用的古籍片段 |
| `feature_mapping` | 现实特征到古典概念的映射 |
| `supporting_reasoning` | 支持解释 |
| `counter_reasoning` | 反向解释 |
| `unknowns` | 无法解释或证据不足部分 |
| `mapping_confidence` | 古典映射置信度 |
| `reviewer` | 人工审核人 |
| `published_version` | 发布版本 |

### 五行映射附加字段

- 现实功能特征；
- 对应古籍规则；
- 当前五行权重；
- 权重理由；
- 禁止永久归类说明；
- 反向解释。

系统不能因为事件属于金融、战争、科技或疫情，就自动指定五行属性。

## 十三、情景推演数据契约

每项预测必须拆成多个情景，而不是输出单一确定结论。

| 字段 | 含义 |
|---|---|
| `forecast_id` | 预测编号 |
| `event_id` | 对应事件 |
| `issued_at` | 发布时间 |
| `valid_until` | 观察截止时间 |
| `scenario` | 情景描述 |
| `probability_band` | 低／中／高或区间，不使用伪精确小数 |
| `supporting_signals` | 支持信号 |
| `trigger_conditions` | 触发条件 |
| `invalidation_conditions` | 失效条件 |
| `settlement_rule` | 判定规则 |
| `settlement_sources` | 结算来源 |
| `status` | 观察中／已触发／已失效／已结算 |

### 验期结算

结算记录至少包含：

- 实际结果；
- 结算时间；
- 使用来源；
- 原判断是否成立；
- 判断偏差；
- 事实错误、映射错误或推演错误的分类；
- 后续修订；
- 原版本保留地址。

## 十四、三种置信度

墨观不使用一个总分掩盖不同层级的不确定性。

### 事实置信度

由来源独立性、来源权威性、时间一致性、地点一致性和主张一致性决定。

### 古典映射置信度

由原文可靠性、历史语义、适用范围、跨时代距离和异说数量决定。

### 预测置信度

由事实基础、历史基准、触发信号和可结算性决定。

三种置信度必须并列显示，不能相互加权成一个“墨观指数”。

## 十五、审核状态

| 状态 | 含义 | 能否公开 |
|---|---|---|
| `draft` | 自动或人工草稿 | 否 |
| `fact_checked` | 事实链已核验 | 只可发布事实部分 |
| `source_checked` | 古籍原文和底本已核验 | 可引用原典 |
| `analysis_reviewed` | 映射与反证已审核 | 可发布分析 |
| `published` | 已正式发布 | 是 |
| `corrected` | 发布后修订 | 是，必须显示修订 |
| `withdrawn` | 因严重问题撤回 | 只显示撤回说明 |

## 十六、修订与不可变记录

1. 发布后的事实、分析和预测均使用版本号；
2. 修改标题不覆盖原版本；
3. 事实修订必须说明错误字段、原因和修订来源；
4. 古典解释修订必须保留原解释和反证；
5. 预测到期后不得删除；
6. 严重错误可以撤回，但必须保留撤回记录；
7. 页面默认显示最新版，同时允许查看历史版本。

## 十七、页面字段映射

| 页面组件 | 必须读取的数据 |
|---|---|
| 首屏时间 | 固定日期、当地时间、时区、数据截止时间 |
| 星空视图 | 天体位置、星官映射、星历来源、数据状态 |
| 天气视图 | 主图层、有效时间、分辨率、来源、质量说明 |
| 事件卡 | 候选池、标题、事实摘要、入选理由、观察窗口 |
| 事件详情 | 事实链、来源、反证、未知事项、后续指标 |
| 象理区 | 原典、时代层级、释义、映射、异说、置信度 |
| 验期区 | 情景、触发条件、失效条件、截止时间、结算状态 |
| 事件研判 | 输入识别、事实核验、拒绝原因、分析草稿 |

## 十八、P0 人工工作流

```text
固定数据截止时间
    ↓
生成天象与天气快照
    ↓
形成约十项事件候选
    ↓
事实核验与评分
    ↓
人工选择三项事件
    ↓
检索已准入古籍片段
    ↓
形成分析与反证草稿
    ↓
人工审核
    ↓
生成情景推演
    ↓
发布固定日期 P0
    ↓
到期结算与复盘
```

## 十九、阶段 0 验收标准

阶段 0 只有同时满足以下条件才算完成：

- P0 页面范围和非目标已经冻结；
- 五类核心对象均有字段契约；
- 所有公开信息都有数据状态；
- 三种置信度已经分开；
- 事实、古籍、分析、预测和结算独立存储；
- 疫情、金融、战争等高风险主题有额外边界；
- 修订和历史版本规则明确；
- 页面组件能够逐一映射到数据字段；
- 剩余未决事项不影响开始真实数据接入。

## 二十、进入阶段 1 前必须确认

### 决定 1｜固定日期

建议继续使用 2026 年 7 月 23 日，以避免重新调整当前原型时间。

### 决定 2｜数据截止时间

建议使用中国标准时间 08:00。这样可以形成稳定的“晨间世界快照”，并为人工审核保留时间。

### 决定 3｜默认地点

建议使用上海作为默认天空观察点，同时保留全球地球视角。

### 决定 4｜首个天气图层

建议优先选择云层。云层视觉直观，全球覆盖明确，也能自然连接天空与地球。

### 决定 5｜三项真实事件

尚未决定。下一步应根据固定日期建立约十项候选事件，按照统一标准选出三项，而不是先指定希望分析的事件。

## 二十一、冻结声明

阶段 1 开始后，除非发现事实错误、安全问题或数据不可获得，P0 不再增加新的数据类别、页面和商业功能。

所有新增想法进入 P1 候选清单，不打断 P0 闭环开发。
