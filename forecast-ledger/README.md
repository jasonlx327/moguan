# 墨观验期账本

本目录保存面向未来、必须到期结算的情景推演。它不保存事实结论，也不把古典解释当作预测证据。

## 基本原则

1. P0 推演在发布时使用此前最近 30 个有效日，不等待未来数据积累后才形成判断；
2. P0 在发布时立即给出当下判断、近日信号、一候走向和三候演变，并固定目标、阈值、触发和失效条件；
3. 每项推演至少包含两个互相区分的情景；
4. 每项推演必须登记现代事实来源、知识库分析 ID、古籍段落、推演方法和责任边界，不输出置信度或概率标签；
5. 每日新增事实只更新验证进度和当前支持度，不得覆盖原始推演；
6. 结论发生实质变化时必须新增带时间戳的版本，并写明改变判断的新证据；
7. 只有结算来源和判定规则完整时，状态才能进入 `watching`；
8. 数据不足的推演必须标记 `blocked`，并列出缺失项；
9. 到期结果、原版本和错误分类不得删除。

## 每日复盘命令

先更新当天已取得的正式来源和各预测的 `.current.json`，再冻结当日复盘：

```bash
npm run review:daily -- --date 2026-07-24
npm run reviews:validate
```

命令会在 `daily-reviews/YYYY-MM-DD.json` 新建一次不可变快照，冻结原始账本及三个当前验证文件的 SHA-256。相同日期再次运行会直接失败，不会覆盖旧复盘。没有新证据时只记录“维持原判断但尚无新增支持”，不得把数据空窗写成验证成功。

## 时间口径

```text
过去 30 个有效日 → 发布当下判断 → 每日验证 → 第 5 日一候小结 → 第 15 日三候复盘
```

每日验证不是重新生成一项事后预测。验证记录只能说明：

- 新数据支持哪个既有情景；
- 离触发或失效条件还有多远；
- 是否出现必须发布新版本的结构性变化；
- 数据延迟、缺失或修订是否影响结算。

用户不需要等待 15 日才获得结果。原始推演发布时就必须给出明确结论；第五日形成可独立阅读的一候小结，第十五日完成三候复盘。出现重大转折时立即发布新版本。

对用户的阶段性反馈必须同时覆盖事实、结构、推演和验证四层；每层给出明确方向、依据与改变条件，不能只展示原始指标。

## 状态

- `draft`：情景已形成，尚未具备观察或发布条件；
- `watching`：结算条件完整，正在观察；
- `triggered`：某一情景触发；
- `invalidated`：原推演整体失效；
- `settled`：已经按规则结算；
- `blocked`：缺少关键结算数据；
- `withdrawn`：因严重问题撤回，保留原因。

## 结算错误分类

- `fact_error`：发布时所依据的事实错误；
- `mapping_error`：古典解释或现代特征映射错误；
- `forecast_error`：事实与解释无误，但情景推演错误；
- `settlement_data_missing`：到期仍没有合格数据；
- `none`：未发现上述错误。
